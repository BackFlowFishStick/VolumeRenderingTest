# STL 现成包调研与自研对比（2026-10-09，主 Agent）

> 背景：D-007 搁置 STL 的原因是包无 STL 支持、自研估 2~3 天（B#5/#6/#7）。本调研评估"用现成包替代自研解析"能否降低成本。
> 使用场景：Unity 2022.3 + URP，运行时从 StreamingAssets/STL/ 直读 61 个 STL（二进制为主，单文件最大 29MB，合计 5,815,720 三角形，见验证记录）。

## 一、候选清单（调研核实过）

| 方案 | 许可/价格 | 运行时 | 二进制+ASCII | 维护 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **pb_Stl**（github.com/karl-/pb_Stl） | MIT，免费 | ✅ 明确支持 | ✅ 自动判别 | 2024-02 停更但功能稳定（ProBuilder 官方同源） | UPM git 引入；`Importer.Import(path)` 一行返回 `Mesh[]`；UInt32 索引或按面数拆分 Mesh 绕过 65k 顶点限制；左/右手系转换 |
| **TriLib 2**（Asset Store 157548） | $45 商业闭源 | ✅ 跨平台 | ✅ | 非常活跃（2026-10 仍更新） | FBX/OBJ/GLTF/STL/PLY/3MF 通吃；只要 STL 则过重 |

## 二、与自研（B#5，估 2~3 天）对比

| 维度 | 自研 StlRuntimeImporter | pb_Stl 接入（推荐） |
| --- | --- | --- |
| 解析器开发 | 0.5~1 天（二进制 84B 头 + ASCII 正则 + 判别） | **0**（MIT，可直接 git 引入或拷源码改造，无法律风险） |
| 坐标系转换 | 自写 LPS→Unity | 内置左右手系转换（医学 STL 为右手系） |
| 65k 顶点限制 | 自行处理 UInt32 索引 | 内置 UInt32 / 自动拆分 |
| 异步/分帧加载 61 文件 | 自写协程 | 拷源码改造（其 Import 是同步的，需自己包协程） |
| 显隐/透明度/筛选/配色 | 0.5~1 天（两方案相同） | 同左，仍需自写 |
| 裁切 shader（B#7） | 1 天（两方案相同） | 同左 |
| 总工作量 | **2~3 天** | **约 1~1.5 天**（解析省下，剩集成） |
| 可控性/定制 | 完全可控 | MIT 源码在手，等同可控 |
| 风险 | 自维护、实现细节坑（顶点超限、大文件卡顿） | 库停更（但格式 20 年未变，风险极低）；依赖管理（git URL 或拷源码进工程） |

## 三、内存提醒（两方案共同的）

61 模型共 5.8M 三角形，hard-normals 模式（顶点不焊接）≈ 17M 顶点，全部加载 Mesh 内存约 400~600MB。缓解手段：按需加载（只加载当前筛选的结构）、smooth 模式焊接顶点、或明确一次只显示子集。这与选哪个解析器无关，属于 #5 实现时的内存设计项。

## 四、结论与建议

1. **推荐 pb_Stl**：MIT、零依赖纯 C#、运行时 API 极简、适配 2022.3。二选一用法：
   - a. manifest.json git URL 引入（依赖外部仓库，符合"包源码不改"铁律 2）；
   - b. 拷其约 300 行 `Runtime/Importer.cs` 进工程（MIT 允许），顺带改造成协程分批加载——**b 更贴合本项目**（无外部依赖 + 直接定制）。
2. 自研工作量从 2~3 天压缩到约 1~1.5 天（剩显隐/配色/坐标变换/异步加载）。
3. 若将来还要 OBJ/PLY/GLTF 等格式再考虑 TriLib 2（$45）；本工程只有 STL，不值。
4. 解除 D-007 搁置与否由用户决定；本调研不改任何工程代码。
