# 08 - 性能优化与调参

体渲染是「逐像素 + 逐采样点」的高密度计算，性能优化的核心就是
**减少采样次数** 和 **减少着色器变体 / 纹理开销**。

## 1. 主要开销来源

按影响排序：

1. **采样步数**（每条射线跑多少次）——影响最大；
2. **像素覆盖面积**（体对象占屏比例）；
3. **分辨率**（3D 纹理越大，缓存 / 带宽压力越大）；
4. **着色器变体数**（编译与切换开销）；
5. **阴影体烘焙**（Compute Shader）；
6. **深度写入**（多体相交时）。

## 2. 关键调参项（C# API / 材质参数）

| 参数 | 默认 | 作用 | 调优建议 |
|---|---|---|---|
| `_SamplingRateMultiplier` | 1.0 | 采样步数 = 512 × 倍率 | 低端机 0.5，高端 1.5~2.0 |
| `rayTerminationEnabled` | true | 累计不透明度接近 1 就停 | 保持开启（白送性能） |
| `visibilityWindow` | (0,1) | 只渲染密度窗口 | 剔除无关组织可加速（跳过采样） |
| `cubicInterpolationEnabled` | false | 三三次插值 | 质量优先才开 |
| `lightingEnabled` | false | 光照 | 开销一般，要效果才开 |
| 阴影（ShadowVolumeManager） | 关 | 3D 阴影 | 最贵，谨慎开 |
| `gradientLightingThreshold` | (0.005,0.02) | 光照过渡 | 画面噪点可调高下限 |
| `minGradient`（等值面） | 0.01 | 等值面阈值 | 噪点多就调大 |

> 材质参数在 `UpdateMatInternal` 里统一写入，改 C# 属性即可。

## 3. 渲染管线与着色器变体

### 3.1 支持三种管线

| 管线 | 着色器目录 | 入口 |
|---|---|---|
| Built-in | `Runtime/Shaders/BuiltIn/` | `UnityCG.cginc` + CGPROGRAM |
| URP | `Runtime/Shaders/URP/` | `Core.hlsl` + HLSLPROGRAM |
| HDRP | `Runtime/Shaders/HDRP/` | `Common.hlsl` / `ShaderVariables.hlsl` |

`ShaderFactory` 通过 `RenderPipelineHelper.GetCurrentPipelineType()` 自动选择；
`BackwardsCompatibility.hlsl` 统一了跨管线的矩阵宏（`UVR_MATRIX_*`）和 `MAIN_LIGHT_DIRECTION_WS`。

### 3.2 着色器关键字（multi_compile）

```hlsl
#pragma multi_compile MODE_DVR MODE_MIP MODE_SURF
#pragma multi_compile __ TF2D_ON
#pragma multi_compile __ CROSS_SECTION_ON
#pragma multi_compile __ LIGHTING_ON
#pragma multi_compile __ SHADOWS_ON
#pragma multi_compile DEPTHWRITE_ON DEPTHWRITE_OFF
#pragma multi_compile __ RAY_TERMINATE_ON
#pragma multi_compile __ USE_MAIN_LIGHT
#pragma multi_compile __ CUBIC_INTERPOLATION_ON
#pragma multi_compile __ SECONDARY_VOLUME_ON
#pragma multi_compile MULTIVOLUME_NONE MULTIVOLUME_OVERLAY MULTIVOLUME_ISOLATE
```

**变体数量 = 各关键字组合的乘积**，关键字越多，编译时间越长、打包越大。
只用到的基础组合（DVR + 无附加）通常够用；不需要的增强尽量别开。

## 4. 深度写入的开销与取舍

`DEPTHWRITE_ON` 让半透明体写出「等效深度」，用于**多个体对象 / 与网格正确遮挡**：

- 开：正确相交，但每像素多一次深度计算，VR 等场景更费；
- 关：省性能，但多个体叠在一起时遮挡会乱。

> 官方 README 提示：如果不需要多数据集相交，可从 `DirectVolumeRenderingShader.shader`
> 里删掉 `#pragma multi_compile DEPTHWRITE_ON DEPTHWRITE_OFF` 这行以减少变体。

## 5. 阴影体的性能

`ShadowVolumeManager` 把 512³ 阴影纹理按 **5×5×5 分块**、每帧只烘焙一块，
所以阴影是**渐进出现**的；光照方向一动就变脏并重烘焙。
真机要省性能时，建议关闭阴影或用更小尺寸。

## 6. 平台注意事项

| 平台 | 注意事项 |
|---|---|
| WebGL | 内存受限，需开 `ALLOW_MEMORY_GROWTH`；无本地文件系统（数据要进 StreamingAssets 或下载） |
| 移动端 | 大纹理（梯度 RGBAHalf 很占内存）+ 采样率高会崩，建议降采样 / 降采样率 |
| 桌面端 | 512³ 数据 + 阴影可承受，注意梯度纹理内存 |

## 7. 示例工程的经验

- `VolumeRenderingSample` 的 UI 暴露了**采样率滑条**（0.1~4.0）和**渲染模式切换**，
  方便实时调参观察；
- lung DICOM（320 × 512 × 512）首次解析约需数十秒，属正常；
- 教学版会把 CT 本体 TF 置全透明，靠分割叠加显示，帧率通常不错。
