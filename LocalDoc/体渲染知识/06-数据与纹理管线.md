# 06 - 数据与纹理管线

> 代码位置：`Runtime/Importing/*`、`Runtime/VolumeData/VolumeDataset.cs`、
> `Runtime/VolumeObject/VolumeObjectFactory.cs`。

## 1. 支持的格式与导入器

`ImporterFactory` 根据格式创建对应导入器：

| 格式 | 导入器类 | 后端 |
|---|---|---|
| DICOM 序列（.dcm） | `DICOMImporter`（图像序列） | openDICOM（内置）或 SimpleITK |
| NRRD（.nrrd） | `SimpleITKImageFileImporter` | **需 SimpleITK** |
| NIFTI（.nii/.nii.gz） | `NiftiImporter` | Nifti.NET（内置） |
| VASP / PARCHG | `ParDatasetImporter` | 内置 |
| RAW（原始二进制） | `RawDatasetImporter` | 内置 |
| 通用图像序列（PNG/JPG...） | `ImageSequenceImporter` | 内置 |

### 重要：SimpleITK

- **NRRD 导入必须启用 SimpleITK**（菜单 `Volume Rendering → Settings → Enable SimpleITK`，
  会下载二进制并定义 `UVR_USE_SIMPLEITK` 宏）；
- DICOM 用内置 openDICOM 即可，无需 SimpleITK；
- 平滑梯度（Smoothed*）也依赖 SimpleITK。

### 示例工程的数据来源

| 数据 | 格式 | 大小/分辨率 | 备注 |
|---|---|---|---|
| `lung/` | DICOM 序列 | 320 张 × ~512×512 | 内置 openDICOM 直接导入 |
| `Chest_CT.nrrd` | NRRD（从 .mrb 解包） | ~84M 体素 | 需 SimpleITK；由 `MrbExtractor` 解包 |

## 2. 从数据到 3D 纹理

### 2.1 归一化（关键！）

着色器里纹理坐标是 0~1，而原始数据范围很大（如 HU -1000~3000），
所以在生成纹理时把数据**线性归一化到 [0,1]**：

```csharp
// VolumeDataset.CreateTextureInternalAsync()
minValue = GetMinDataValue();
maxValue = GetMaxDataValue();
maxRange  = maxValue - minValue;
pixel = (data[i] - minValue) / maxRange;   // → [0,1]
```

这就是为什么传输函数的横轴是 0~1——它对应「归一化密度」。

### 2.2 数据纹理格式

- 优先 `RHalf`（半精度浮点，每体素 2 字节），不支持则 `RFloat`（4 字节）；
- `Texture3D`，`wrapMode = Clamp`；
- 只有 **R 通道**存密度（其它通道闲置）。

### 2.3 梯度纹理格式

- `RGBAHalf`/`RGBAFloat`；
- RGB=梯度分量、A=归一化密度（见 05 章）。

### 2.4 异步与进度

- `GetDataTextureAsync(progressHandler)` / `GetGradientTextureAsync(...)` 走后台线程，
  不阻塞主线程，可用 `IProgressHandler` 显示进度；
- 首次生成大纹理可能耗时数秒~数十秒（示例 DICOM 解析就注明「首次约需数十秒」）。

## 3. 内存估算

以 512×512×320（~8388 万体素）为例：

| 纹理 | 格式 | 每体素 | 总内存 |
|---|---|---|---|
| 数据 `_DataTex` | RHalf | 2 B | ~168 MB |
| 梯度 `_GradientTex` | RGBAHalf | 8 B | ~671 MB |
| 阴影 `_ShadowVolume`（若开启） | RHalf(512³) | 2 B | ~268 MB |
| 传输函数 `_TFTex` | RGBAHalf(1024×2) | — | 很小 |

> 结论：**梯度纹理最占内存**；`RGBAHalf` 是 8 字节/体素。
> 若开启阴影（512³）还会再加几百 MB。移动端/低内存平台要留意。

## 4. 从 VolumeDataset 到可见体对象

```csharp
// VolumeObjectFactory
VolumeRenderedObject volObj = await VolumeObjectFactory.CreateObjectAsync(dataset, progress);
// 或同步
VolumeRenderedObject volObj = VolumeObjectFactory.CreateObject(dataset);
```

创建时自动：

- 实例化 `VolumeContainer`（单位立方体网格 + MeshRenderer）；
- 创建体渲染材质（`ShaderFactory` 按渲染管线选着色器）；
- 生成并绑定 3D 数据纹理、噪声纹理（512×512）、1D/2D 传输函数；
- 设置 `dataset.scale` / `dataset.rotation`（保持真实尺寸/朝向）。

## 5. 路径解析（示例工程的坑）

`.dcm/.nrrd` 是 Unity 不认识的资产，不能用 `Resources.Load`。
示例工程用 `DatasetPathResolver` 统一解析：

```csharp
// 优先级：StreamingAssets → 编辑器下回退 Assets/Resources
Application.streamingAssetsPath/...  →  UNITY_EDITOR: Application.dataPath/Resources/...
```

解包产物（Chest_CT.nrrd 等）放在 `Assets/StreamingAssets/Datasets/`，
这样**编辑器 Play 模式能直读，将来打包也能用**（StreamingAssets 会进包里）。
